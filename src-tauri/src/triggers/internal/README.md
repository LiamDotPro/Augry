# Internal triggers (`tg`)

Fires when something happens inside Terminal Grid itself: an agent finishes, a
command fails, a worktree is created, a note is saved.

Source id `tg`. It lives in the app, not in a crate, because only the app sees
these events. It has the same split as a trigger crate and the same eight
sections here. Everything it fires starts with `tg.`.

Generated by `trigger_core::kinds_markdown(KINDS)`; the test

stale. The expected text is in the failure message.

What each kind means:

- `tg.agent-finished`: a coding agent in a pane stopped running.
- `tg.command-failed`: a command ended with an exit code other than 0, or with
  the code the rule names.
- `tg.command-slow`: a command ran for more than `longer_than_ms`.
- `tg.output-matched`: one line of terminal output matched the pattern.
- `tg.bell`: a terminal rang its bell.
- `tg.task-reported`: an agent wrote a new task line.
- `tg.pane-opened-in-repo`: a new pane opened inside a git repository. A pane
  that opens outside one never fires.
- `tg.worktree-created`, `tg.worktree-removed`: a worktree was created or
  removed from the app.
- `tg.review-staged`: files were staged in the review panel.
- `tg.note-saved`: a note was saved from the notes editor.
- `tg.focus-entered`: a pane got the focus.
- `tg.app-started`: the app started.

## Rule fields

The `when` object of a trigger, parsed by `rule.rs`. Unknown fields are an
error, so a typo shows up in the editor.

| Field | Kinds | Required | Default | Meaning |
|---|---|---|---|---|
| `repo` | every kind except `tg.bell`, `tg.note-saved` and `tg.app-started` | no | any repository | Absolute path of a repository, after variables such as `${repo.root}` are expanded. Fires for that repository and for panes inside it. |
| `agent` | `tg.agent-finished` | no | any agent | Glob for the agent name, ignoring case. |
| `exit_code` | `tg.command-failed`, `tg.command-slow` | no | failed: any code except 0. slow: any code | Fires only for this exit code. |
| `longer_than_ms` | `tg.command-slow` | yes | | Fires when the command ran for more than this many milliseconds. |
| `pattern` | `tg.output-matched` | yes | | Regular expression (Rust `regex` syntax), ignoring case, tried on each line of output. A pattern that is invalid or compiles to more than 256 KiB is refused with the reason. |
| `glob` | `tg.note-saved` | no | any note | Glob matched against the path below the notes folder, with `/` separators. `*` stays inside one folder, so use `**/*.md` for any depth. |

## Payload

What an event carries, available to steps as `${trigger.<field>}`. Ids, paths,
names and numbers only. Never the full output of a terminal.

| Field | Meaning |
|---|---|
| `pane` | Id of the terminal pane |
| `cwd` | Working directory of the pane |
| `repo` | Root of the repository (`tg.pane-opened-in-repo`, worktree and review kinds) |
| `agent` | Name of the agent that finished |
| `exit_code` | Exit code of the command |
| `duration_ms` | How long the command ran, in milliseconds |
| `line` | The line that matched, cut to 200 characters |
| `path` | Absolute path of the worktree or the note |
| `relative` | Path of the note below the notes folder |
| `branch` | Branch of a new worktree, left out when unknown |
| `files` | How many files were staged |

## Platforms

All three. Nothing here talks to the OS. A kind only fires when a feed in the
app publishes its signal, and some feeds depend on the shell.

| Platform | How it is detected | Limits |
|---|---|---|
| macOS | The app publishes an `InternalSignal` | Command and bell kinds need the shell integration marks |
| Windows | The same | The same |
| Linux | The same | The same |

## Permissions

None. The source reads nothing from the OS.

## Example

```json
{
  "id": "build-failed",
  "kind": "tg.command-failed",
  "when": { "repo": "${repo.root}" }
}
```

## Develop

| File | What it holds |
|---|---|
| `mod.rs` | `InternalSignal`, `InternalSource` (the `Source` implementation, cheap to clone) and its `publish` and `wants_output` |
| `kinds.rs` | `KINDS`: the thirteen kinds with their `when` and payload fields, and the test that keeps the table above current |
| `rule.rs` | The typed `Parsed` and `Filter`, and `parse`, which also compiles the globs and the pattern. Pure, unit tested |
| `logic.rs` | Pure: `step(&[Armed], &InternalSignal)` returns the rules that fire and their payloads |
| `logic/tests.rs` | The tests of `step` |

The app feeds the source with `TriggerService::publish_internal(signal)`, and
the terminal reader asks `TriggerService::wants_output()` before it assembles
lines.

```
cd src-tauri
cargo test -p terminal-grid triggers::internal
cargo fmt --check
```

A bug in what fires goes into `logic/tests.rs` first, as the signal that caused
it.

## Known limits

- `repo` compares paths component by component and does not resolve symlinks
  or `..`. The feeds give canonical paths.
- Rules run on the thread that publishes the signal, so a pattern is matched on
  the terminal reader thread. The pattern is compiled once when the rule starts.
- Each rule has the hub's two second cool down, so a noisy pattern fires at most
  once every two seconds.
- `tg.agent-waiting`, `tg.note-tagged`, `tg.file-dropped`, `tg.file-opened` and
  `tg.tray-menu` do not exist yet.
